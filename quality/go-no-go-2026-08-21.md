## Check 2 — why it cannot pass, and why that is not a product statement

A scorecard entry names the commit the gate ran against. Committing that entry
produces a new commit, which the entry cannot name; merging it produces another.
So `scorecard.commit == HEAD` is satisfiable only when the scorecard is never
committed — which is the state #13 deliberately created, for a good reason.

The gate did pass on this content: `ed040b7` scored **13 passed, 0 failed, 0
skipped** locally with a real database present, and all three required checks
were green on `4261bde`, whose delta to `ed040b7` is the scorecard file and its
evidence directory — no product code. The check as written cannot express that.
Worth an operator decision on the wording; not worth pretending it passed.

## Check 4 — the real blocker

```
site_config.admin_email = ''      (empty)
profiles where role='admin' = 0
```

There is no deployment target either, so `NEXT_PUBLIC_SITE_URL`, `CRON_SECRET`
and the rest have no values to be sane about. Both halves lead to the same
place: the platform cannot be operated until someone holds the cockpit, and
**setting `admin_email` is L5** — `EXECUTION_POLICY.md` names it directly,
"Changes who holds the cockpit". No agent may do it under any instruction.

This check previously asserted `ADMIN_EMAIL`, the environment variable, and
would have reported a clean environment against this exact state. It now asserts
the row the trigger reads, and additionally that no profile yet exists for that
address — because the grant fires once, at INSERT, and a sprung trap looks
identical to an unsprung one from outside. `[D-96]`

## What would change the verdict

1. The operator sets the row, **before anyone signs in with that address**:
   ```sql
   update public.site_config set value = to_jsonb('tom@gteveryday.com'::text)
    where key = 'admin_email';
   ```
2. Then signs in once at `/login` — the OTP tab needs no password.
3. A deployment target exists and its variables are set per `docs/DEPLOYMENT.md`.

Step 3 at the real origin also needs a domain pointed at it, which is L5 #5.
